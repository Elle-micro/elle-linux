Latte-clean-old startup segfault — root cause and fix
Date: 2025-09-04

Symptom
- Running: latte_clean_old --help
- Immediate SIGSEGV during startup, before any usage text.
- Backtrace pointed to ElleInitRunOptions() called from ElleInit() in main().

Trigger context
- main() called ElleInit() before ParseOptions().
- ElleInitRunOptions() initializes defaults and then calls ElleSetOptNames(...).
- Crash occurred right after offsets were set, at/around ElleSetOptNames().

Root cause
- Undefined behavior from mismatched function signatures and implementations:
  - Functions declared as returning int but with no return statement:
    - ElleSetOptNames(...)
    - ElleSetOptName(char* names[9])
    - ElleGetOptNames(char* names[9])
  - On AArch64/Clang this caused a bad return value/stack state, leading to a segfault when ElleSetOptNames() was called during initialization.

The fix applied
- Change these functions to return void (they are used only for side effects):
  - In elle/elle/basecode/runopts.h:
    - void ElleSetOptNames(const char*, const char*, const char*, const char*, const char*, const char*, const char*, const char*, const char*);
    - void ElleSetOptName(char* names[9]);
    - void ElleGetOptNames(char* names[9]);
  - In elle/elle/basecode/runopts.cc:
    - Update definitions to match void signatures.
    - Implement ElleSetOptNames(...) by composing a local char* names[9] and forwarding to ElleSetOptName(names).

Verification
- Rebuilt latte_clean_old.
- latte_clean_old -h now prints usage (note: short option -h is recognized; --help is not).
- Headless smoke test runs: latte_clean_old -n -i elle/elle/processes/latte-clean-old/res50.elle
  - Observed time steps advancing without crash.

How to avoid this next time
- Turn UB into compile errors:
  - Add -Werror=return-type (and keep -Wall -Wextra -Wpedantic).
- Add a tiny CI smoke test that runs:
  - latte_clean_old -h
  - latte_clean_old -n -i elle/elle/processes/latte-clean-old/res50.elle (or another bundled sample) and checks it reaches a few steps.
- Prefer consistent prototypes: ensure headers and sources agree; functions declared non-void must return a value on all paths.
- Note: the option parser doesn’t support GNU long options; use -h instead of --help.

Quick repro/diagnostic notes
- If a similar early-startup segfault reappears:
  1) Run under gdb and bt to confirm crash site (ElleInitRunOptions is a usual hotspot during startup).
  2) Temporarily add log prints around suspicious calls in ElleInitRunOptions() to bracket the failing line.
  3) Scan for non-void functions lacking return statements or header/impl signature mismatches in the touched area.
