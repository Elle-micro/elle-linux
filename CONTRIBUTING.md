# Contributing Guidelines

Thank you for your interest in contributing. This document summarizes the expected developer workflow for builds, formatting, and static analysis.

## Build Workflow

Primary entrypoint: `scripts/build_conan.sh`

Examples:

```
# Release (default)
./scripts/build_conan.sh

# Debug
./scripts/build_conan.sh debug

# RelWithDebInfo, enable warnings-as-errors
WARN_AS_ERROR=ON ./scripts/build_conan.sh relwithdebinfo

# Clean + regenerate lockfile + package artifacts
CLEAN=1 LOCK=1 PACKAGE=1 ./scripts/build_conan.sh release
```

Notable env flags:

| Variable | Effect |
|----------|--------|
| BUILD_DIR | Alternate build directory (default: `build`) |
| INSTALL_PREFIX | Staging install prefix (default: `build/stage`) |
| ELLE_GUI | Build GUI components (ON/OFF, default OFF) |
| ELLE_USE_MPI | Enable MPI features (ON/OFF, default OFF) |
| WARN_AS_ERROR | Treat compiler warnings as errors (default OFF locally, ON in CI) |
| CLEAN | If 1, removes the build directory before configuring |
| LOCK | If 1, generates/updates `conan.lock` |
| USE_LOCK | If 1 and lock exists, uses lockfile for dependency resolution |
| PACKAGE | If 1, runs CPack to produce tarball / deb (where supported) |

## Code Style (clang-format)

The project ships a `.clang-format` derived from LLVM style (2‑space indent, 120 column limit, regrouped+sorted includes). We intentionally avoid a one-time massive reformat; instead we check only what you changed.

### Changed-files mode
`./scripts/format-check.sh` now examines only C/C++ files that differ from a base branch (default: `origin/master`, fallback `origin/main`, then previous commit). This keeps diffs reviewable and avoids churn in untouched legacy code (notably the `wxplotcode/` subtree).

### Exclusions
Legacy or low‑value refactor areas can be excluded by regex (default exclusion: `wxplotcode/`). You may override via an environment variable.

### Environment variables
| Variable | Purpose | Default |
|----------|---------|---------|
| `FORMAT_BASE_REF` | Git reference to diff against | auto-detect (`origin/master` / `origin/main`) |
| `FORMAT_EXCLUDE_REGEX` | Egrep regex of paths to skip | `wxplotcode/` |
| `FORMAT_FIX` | If `1`, apply formatting instead of only checking | `0` |

### Typical use
Check your staged changes while on a feature branch:
```
./scripts/format-check.sh
```
Auto-fix any violations for just the changed files:
```
FORMAT_FIX=1 ./scripts/format-check.sh
```
Temporarily include legacy GUI code in the check:
```
FORMAT_EXCLUDE_REGEX="" ./scripts/format-check.sh
```
Compare against a different base (e.g., a long‑running integration branch):
```
FORMAT_BASE_REF=origin/integration ./scripts/format-check.sh
```

If CI or the pre-commit hook warns about formatting, re-run with `FORMAT_FIX=1`, stage the results, and recommit.

## Static Analysis (clang-tidy)

We provide a curated `.clang-tidy` focused on actionable categories: `bugprone-*`, `performance-*`, `modernize-*`, selected readability and analyzer checks. Some noisier checks (magic numbers, certain core guideline ownership checks) are disabled initially to ease adoption.

Run locally after a build (needs `compile_commands.json` generated by CMake/Conan toolchain):

```
./scripts/tidy-check.sh              # Defaults to 'build'
./scripts/tidy-check.sh build-debug  # Alternate build dir
```

The script currently limits itself to the first ~200 translation units for speed. Adjust once the baseline is clean.

## Incremental Quality Strategy

1. New code should be warning-free with `WARN_AS_ERROR=ON` locally before pushing.
2. Prefer applying clang-format only on changed lines/files to avoid churn.
3. When fixing a clang-tidy issue, keep the change logically separate from feature commits if it touches many lines.

## Git Hook

The hook below does two things:
1. Warns (but does not block) if staged C/C++ files are not clang-formatted.
2. Prevents committing directly to `master` by auto-creating a feature branch (unless you explicitly opt out).

Install:

```
cat > .git/hooks/pre-commit <<'EOF'
#!/usr/bin/env bash
set -euo pipefail

BRANCH=$(git rev-parse --abbrev-ref HEAD 2>/dev/null || echo unknown)
MAIN_BRANCH=master   # Adjust if you also allow 'main'

# If on master, auto-create a branch to avoid direct commits.
if [ "$BRANCH" = "$MAIN_BRANCH" ]; then
	base_commit=$(git rev-parse HEAD)
	ts=$(date +%Y%m%d-%H%M%S)
	new_branch="feat/${ts}-auto"
	echo "[pre-commit] Direct commits to '$MAIN_BRANCH' are discouraged. Creating branch '$new_branch'." >&2
	git checkout -b "$new_branch" "$base_commit" || {
		echo "[pre-commit] Failed to create branch. Abort." >&2
		exit 1
	}
	BRANCH=$new_branch
fi

changed=$(git diff --cached --name-only --diff-filter=ACMRT | grep -E '\\.(c|cc|cpp|h|hpp)$' || true)
[ -z "$changed" ] && exit 0

echo '[pre-commit] Checking clang-format (warning only)...'
if ! clang-format --dry-run --Werror $changed 2>/dev/null; then
	echo '[pre-commit] WARNING: Formatting issues detected. Commit will proceed.' >&2
	echo '          Run: clang-format -i (affected files) and recommit.' >&2
fi

exit 0
EOF
chmod +x .git/hooks/pre-commit
```

To bypass branch auto-creation temporarily (not recommended), manually create and switch to a branch before staging changes.

## Dependency Locking

Use `LOCK=1` when you intentionally update dependencies; commit the resulting `conan.lock`. Regular feature branches should rely on `USE_LOCK=1` for reproducibility.

## Submitting Changes

1. Branch from `master`.
2. Small, focused commits (build changes, formatting, behavior each separated when practical).
3. Ensure build passes locally: `WARN_AS_ERROR=ON ./scripts/build_conan.sh`.
4. Run `./scripts/format-check.sh` and optionally `./scripts/tidy-check.sh`.
5. Open a PR; include context + rationale, especially for dependency or style config changes.

---

Questions or proposals to adjust style / static analysis scope? Open an issue or start a discussion before broad reformatting.
